## §1 新会话预设词（直接复制粘贴）

**用法**：新建会话 → 把下面整块贴进去 → 填掉「客户信息」里你知道的部分 → 发送。
**不知道的项一律写「未知」，不要猜**——预设词里已写明不许编。

```text
执行一次 LLM 成本审计。

第一步：加载技能 llm-cost-audit，严格按技能里的流程和检查表执行。

客户信息（不知道的写「未知」，禁止猜测或编造）：
- 客户 / 项目名：
- 本次档位（免费诊断 / 完整审计 / 实施+持续）：
- 数据来源（账单 CSV / 用量导出 / 只读 Admin key / 网关日志 / 都没有）：
- 数据时间窗：
- 用了哪些供应商：
- 产品做什么、大概多少用户：
- 有没有维度标签（功能 / 端点 / 环境 / 租户）：

硬性要求（这些是产品的一部分，不许省）：
1. 报告里每一个数字都要有来源或算式，附件里能复核
2. 必须给出两个节省数字：「已识别节省」和「已验证节省」，绝对不许合并成一个
3. 必须有「诊断深度声明」（结构性诊断 vs 行为性诊断）放在第一页
4. 必须有「不建议做」一页
5. 严禁编造客户名、评价、logo、省费率、案例
6. 交付 .md 和 .html 两种格式（用户没有 Markdown 阅读器）
7. 结论先行，中文为主，量大用表格

做完之后：
按 _docs/审计业务-预设词与案例模板-20261022.md 的 §2 结案模板，写一份脱敏案例，
存到 _docs/cases/<日期>-<客户代号>.md，并更新 _docs/cases/INDEX.md，
最后按 §3 的清单决定要回写技能里的哪几节。
```

## §2 结案模板（每单做完必填，脱敏后入库）

> 目的不是交差，是让下一单更准。所以「客户没做的项」和「偏差分析」比「省了多少」更重要。

```markdown

## 1. 客户画像（脱敏）
- 行业 / 规模（员工数或月流水区间）：

- 供应商与月 API 花费区间：

- 基线的漏洞（比如缺标签、有免费额度混入）：

## 3. 诊断深度
- 本次是结构性还是行为性诊断：
- 客户为此提供了什么（只读 key / 改 base_url / 埋点）：
- 因此没能覆盖什么：

## 4. 命中的浪费项
| W 编号 | 命中 | 证据 | 估算金额 |
|---|---|---|---|
|  | 是/否/不适用 |  |  |

## 5. 提议的修法
| 修法 | 杠杆编号 | 已识别节省 | 工程量 | 客户做了吗 |
|---|---|---|---|---|
|  |  |  | quick win/一周/结构性 | 做了/没做/部分 |

## 6. 客户没做的项（重要）

- 沟通上踩的坑：
```

## §3 进化机制（每次结案后固定动作）

| 步骤 | 做什么 | 谁做 |
|---|---|---|
| 1 | 按 §2 写脱敏案例 | 新会话 |
| 2 | 更新 `_docs/cases/INDEX.md`（一行一条：日期 / 行业 / 档位 / 已验证节省 / 最大教训） | 新会话 |
| 3 | 按 §2 第 11 节回写技能对应章节 | 新会话 |
| 4 | 每 5 单做一次总复盘：哪些话术失效了、哪些项反复被拒 | 主会话 |
| 5 | 把稳定的结论固化成技能的「默认假设」 | 主会话 |

**三条不许破的规矩：**

1. **案例必须脱敏**：客户名与可识别信息一律代号化；未经书面同意不得公开任何细节。
2. **偏差必须写**：只写「省了多少」不写「哪里没算准」的案例没有进化价值。
3. **回写才算结案**：没有回写技能的案例，等于白做。
