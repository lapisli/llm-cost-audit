# 国内主流大模型定价与省钱机制全表

> 调研目的：为「LLM 成本审计 + 降本实施」服务建立可引用、可复现的定价底稿。
> 调研方式：逐家抓取官网定价页（web_fetch 同步抓取，无后台任务）。
> 抓取时间：本轮调研当日（页面均标注「最近更新时间」，见各节）。

## 0. 阅读说明（必读）

### 0.1 性质标注规则

| 标注 | 含义 |
| --- | --- |
| **官方** | 数字直接来自厂商官方文档/定价页，附 URL，可直接引用给客户 |
| **官方-渠道价** | 官方页面，但是**转售渠道**（如阿里云百炼转售 Kimi），非模型厂商自营价 |
| **第三方** | 第三方统计站/媒体，未经厂商页面确认，**不可直接写进交付物** |
| **换算** | 由本人币价按汇率折算，**非官方美元定价** |
| **未核实** | 只有线索、没有拿到可引用页面 |

### 0.2 美元口径的处理方式（重要）

厂商中只有 DeepSeek 官方同时给出人民币与美元两套页面；其余各家官网只以「元/百万 tokens」标价。
因此本文所有 `$` 列均为 **按 1 USD = 7.10 CNY 换算的估算值**，性质 = **换算（非官方）**。
对客户交付时请只引用 `元` 列，`$` 列仅用于跨厂商横向比价，并注明汇率假设。

### 0.3 计费口径的三个陷阱（审计话术的立足点）

1. **「输入单价」通常不等于你实际付的输入价。** 未命中缓存与命中缓存是两套价，差 3～50 倍。
2. **部分厂商把「缓存存储」单独计时收费**（按 元/百万 tokens/小时），这是传统 TCO 表里最容易漏的一项。
3. **上下文长度阶梯价**会按输入长度切档，同一个模型名在不同长度下是两个价。

### 1.3 ★ 错峰（空闲）时段具体是几点到几点

官方原文（**官方**，同页脚注 2）：

> 空闲时段价格为高峰时段价格的一半。北京时间**周一至周五（不含中国法定节假日）9:00 - 12:00、14:00 - 18:00 为高峰时段**；**其余时段，包括周末及中国法定节假日全天均为空闲时段**。

翻译成可执行的排班表：

| 时段 | 档位 | 相对高峰折扣 |
| --- | --- | --- |
| 工作日 09:00–12:00 | 高峰 | 1.0×（基准） |
| 工作日 12:00–14:00 | **空闲** | **5 折** |
| 工作日 14:00–18:00 | 高峰 | 1.0× |
| 工作日 00:00–09:00 | **空闲** | **5 折** |
| 工作日 18:00–24:00 | **空闲** | **5 折** |
| 周六、周日全天 | **空闲** | **5 折** |
| 中国法定节假日全天 | **空闲** | **5 折** |

**注意**：DeepSeek 现在的框架是「高峰时段」而不是老文档里的「夜间优惠时段」。
不要说「DeepSeek 夜间打折」，要说「**工作日 9-12 点、14-18 点之外全部是空闲时段，价格减半**」。
这个框架对客户的启发更大：**把批处理任务挪到午休、晚上和周末，输入输出全项直接砍一半**，且不需要改任何代码。

### 1.4 ★ 缓存命中价 vs 未命中价的差（审计最有说服力的一组数）

| 模型 | 档位 | 未命中 | 命中 | 倍数 |
| --- | --- | --- | --- | --- |
| deepseek-flash | 空闲 | 1 元 | 0.02 元 | **50 倍** |
| deepseek-flash | 高峰 | 2 元 | 0.04 元 | **50 倍** |
| deepseek-v4-pro | 空闲 | 4.5 元 | 0.15 元 | **30 倍** |
| deepseek-v4-pro | 高峰 | 9.0 元 | 0.30 元 | **30 倍** |

**结论**：缓存命中率从 0% 提升到 96%，在 DeepSeek 上能把输入侧成本压到原来的约 $\frac{0.04\times96 + 2\times4}{2\times100} \approx 5.9\%$（以 flash 高峰、96% 命中率估算）。
反过来说：**每次请求只要前缀变了，命中率就崩，价格立刻跳 30～50 倍。** 这是审计的第一抓手。

## 4. Kimi（月之暗面 / Moonshot）

### 4.1 官网情况

来源：<https://platform.kimi.com/docs/pricing/chat> 与 `.md` 端点 —— **抓取失败（数字部分）**
原因：Kimi 定价表由前端动态渲染，官方 `.md` 端点返回的是 **空表格**（`<table><thead><tr /></thead><tbody /></table>`），拿不到任何数字。
**严禁凭印象填数**，此处只记录官方能确证的机制。

### 4.2 官方可确证的计费机制（**官方**）

- 模型推理**按量计费，不提供订阅制**；官方明确要与 Kimi 会员、Kimi Code 区分。
- Kimi API 对**重复的请求前缀自动启用上下文缓存**。
- 缓存条目按 TTL 分 **5min / 1h** 两档，不指定 TTL 时默认 **5min 档**。
- K3 系列：**缓存写入单独按 TTL 计费**；有效期内命中缓存的输入**仅按「输入价格（缓存命中）」计费**，命中后缓存有效期**自动续期，不再收取缓存写入费用**。
- Token 换算：1 Token ≈ **1.5–2 个汉字**。
- 文件接口（内容抽取/文件存储）**限时免费**。
- 另有独立页：批量推理定价 <https://platform.kimi.com/docs/pricing/batch>、联网搜索定价 <https://platform.kimi.com/docs/pricing/websearch>（本轮未抓取）。

## 9. 给「LLM 成本审计」服务的落地检查表

### 9.1 客户访谈必问（问完就能估出省钱空间）

1. 你们现在用的是哪家的哪个模型？（**先用「元/百万 token」确认单价，别信印象**）
2. 上一次账单里，**缓存命中 token 数**是多少？未命中是多少？
3. 单次请求的**输入长度**分布在多少区间？有多少超过 32K / 512K 台阶？
4. 有没有**不需要实时返回**的任务（报表、批处理、离线抽取）？→ 能否挪到 DeepSeek 空闲时段或走 Batch？
5. 有没有在用 `priority` / 高优先级服务等级？→ 是不是其实不需要？
6. 用的是**自营**还是**云厂商转售渠道**？（如 Kimi 自营 vs 百炼）
7. 免费额度用完了吗？过期了吗？（腾讯混元 100 万 tokens **1 年过期**，极易浪费）

### 9.2 三条「改一行代码就省钱」的动作

| 动作 | 依据 | 预期 |
| --- | --- | --- |
| 把批处理任务排到工作日的 12–14 点、18 点后，或周末 | DeepSeek 空闲时段（**官方**） | 输入+输出**全项 5 折** |
| 保持前缀稳定（系统提示、工具定义放最前且不变） | DeepSeek 缓存命中 30–50×（**官方**） | 输入侧可降 1–2 个数量级 |
| 把单次输入压在 32K 以内 | 智谱 GLM-5 系列 32K 台阶（**官方**） | 输入+输出各降 25%–33% |

### 9.3 报价时最容易算错的三个点（主动说出来就是专业度）

1. 百炼 **Batch File ≠ Batch Chat**（一个 5 折，一个原价）。
2. 智谱 **缓存存储**目前「限时免费」，**免费期结束后会恢复收费**，长期 TCO 模型要留这一项。
3. 腾讯混元**正在迁移到 TokenHub**，旧平台停止支持新购——给客户做新选型时旧文档价格会失效。
